# Security Policy

## Reporting a vulnerability

Do not report exploitable vulnerabilities in public issues.

Contact the repository owner through a private security advisory or a verified private contact channel. Include:
- Affected version / commit.
- Impact and attack prerequisites.
- Reproduction steps or proof of concept that avoids accessing real user data.
- Suggested mitigation, if known.

## Response expectations

Acknowledge and triage reports as soon as practical. Timelines depend on severity, reproducibility, and maintainer capacity. Coordinate disclosure with the reporter.

## Scope

This starter repository is a demonstration baseline. Do not test systems you do not own or have explicit written authorization to assess.
